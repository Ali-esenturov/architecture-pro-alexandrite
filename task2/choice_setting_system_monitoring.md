# Выбор метрик и настройка мониторинга системы

## Подходы к мониторингу по частям системы

| Часть системы                | Подход | Причина выбора |
|-----------------------------|--------|----------------|
| Онлайн-магазин API          | RED    | Пользовательский HTTP-сервис, важны latency и ошибки |
| CRM API                     | RED    | Операторский интерфейс, чувствителен к задержкам |
| MES API                     | RED    | Контроль доступности и стабильности |
| MES calculation workers     | USE    | CPU и memory-bound вычисления |
| RabbitMQ                    | USE    | Очереди и насыщение - ключевые показатели |
| Базы данных                 | USE    | Контроль утилизации и saturation |
| Бизнес-процессы заказов     | Custom | Не покрываются стандартными подходами |

## Метрики системы

| Метрика | Где отслеживается | Зачем нужна | Ярлыки (labels) |
|-------|------------------|-------------|-----------------|
| HTTP request latency | Shop, CRM, MES API | Контроль времени ответа | service, endpoint, method, status_code |
| Request rate (RPS) | Все API | Анализ нагрузки и роста | service, endpoint |
| Error rate | Все сервисы | Обнаружение деградаций и регрессий | service, endpoint, error_type |
| Queue length | RabbitMQ | Индикатор перегрузки MES | queue_name |
| Queue wait time | RabbitMQ / MES | Контроль SLA асинхронной обработки | queue_name |
| Price calculation duration | MES workers | Анализ сложности расчётов | complexity, worker_id |
| Active workers count | MES workers | Контроль пропускной способности | worker_type |
| DB query duration | CRM DB, MES DB | Поиск медленных запросов | db, query_type |
| DB connections count | Все БД | Предотвращение исчерпания ресурсов | db |
| Cache hit ratio | Redis | Оценка эффективности кеша | cache_key_type |
| Cache latency | Redis | Контроль влияния кеша | operation |
| Orders per status | CRM, MES | Выявление узких мест процесса | status |
| Time between statuses | CRM, MES | Анализ bottleneck’ов | from_status, to_status |
| SLA price calculation | MES | Контроль бизнес-ожиданий | complexity |
| CPU utilization | Все сервисы | Основа для масштабирования | service, instance_id |
| Memory utilization | Все сервисы | Предотвращение OOM | service, instance_id |
| DLQ messages count | RabbitMQ | Контроль ошибок обработки | queue_name |

## Мотивация по метрикам

| Метрика | Где отслеживается | Зачем нужна (бизнес-мотивация) |
|--------|------------------|---------------------------------|
| HTTP request latency | Shop, CRM, MES API | Позволяет контролировать скорость работы системы для клиентов и операторов и выявлять деградации до появления жалоб |
| Request rate (RPS) | Все API | Показывает реальный рост нагрузки и позволяет планировать масштабирование до возникновения перегрузок |
| Error rate | Все сервисы | Позволяет быстро обнаруживать сбои и регрессии, напрямую влияющие на количество жалоб и отмен заказов |
| Queue length | RabbitMQ (price calc) | Показывает, справляется ли система с потоком заказов; рост очереди означает задержки в обработке заказов |
| Queue wait time | RabbitMQ / MES | Отражает фактическое ожидание клиента до начала расчёта стоимости, критично для SLA |
| Price calculation duration | MES workers | Позволяет выявлять тяжёлые изделия, оценивать сложность заказов и прогнозировать сроки выполнения |
| Active workers count | MES workers | Позволяет контролировать пропускную способность расчётов и принимать решения о масштабировании |
| DB query duration | CRM DB, MES DB | Помогает находить причины медленных дашбордов и снижать потери рабочего времени операторов |
| DB connections count | Все БД | Предотвращает отказ системы из-за исчерпания соединений при росте нагрузки |
| Cache hit ratio | Redis | Демонстрирует эффективность кеширования и подтверждает снижение нагрузки на базы данных |
| Cache latency | Redis | Позволяет убедиться, что кеш ускоряет систему, а не становится новым узким местом |
| Orders per status | CRM, MES | Даёт бизнесу наглядную картину, на каком этапе «застревают» заказы и где теряется время |
| Time between statuses | CRM, MES | Позволяет измерять эффективность каждого этапа производства и выявлять узкие места процесса |
| SLA price calculation | MES | Формализует ожидания бизнеса по срокам расчёта и позволяет контролировать их выполнение |
| CPU utilization | Все сервисы, MES workers | Позволяет понять, хватает ли вычислительных ресурсов для текущей и будущей нагрузки |
| Memory utilization | Все сервисы, MES workers | Предотвращает аварийные остановки сервисов из-за нехватки памяти |
| DLQ messages count | RabbitMQ | Ранний сигнал о сбоях обработки заказов, позволяющий избежать потери данных и ручных разборов |

## Высокоуровневый план действий

| Метрика | План действий |
|--------|---------------|
| HTTP request latency | Настроить сбор метрик на уровне API; создать дашборды в Grafana; настроить алерты на превышение порогов |
| Request rate (RPS) | Подключить мониторинг RPS; собрать и агрегировать метрики в time-series базе |
| Error rate | Настроить логирование ошибок с тегами сервиса и эндпоинта; создать алерты на рост ошибки выше порога |
| Queue length | Настроить мониторинг очередей RabbitMQ; визуализировать длину очередей; создать алерты на превышение |
| Queue wait time | Собирать метрики времени ожидания сообщений; визуализировать среднее и 95-й перцентиль; алерты при росте |
| Price calculation duration | Логировать время расчёта по каждому заказу; агрегировать по типу изделия; дашборды и алерты |
| Active workers count | Собирать метрики активных воркеров; дашборды с динамикой; рекомендации по масштабированию |
| DB query duration | Включить slow query logging; собирать статистику в TS-базу; визуализировать медленные запросы |
| DB connections count | Собирать метрики текущих соединений; алерты на превышение лимита; рекомендации по пулу соединений |
| Cache hit ratio | Собирать метрики cache hit/miss; дашборд с эффективностью кеша; алерты при падении hit ratio |
| Cache latency | Логировать время операций Redis; визуализировать 95-й перцентиль; алерты на превышение порога |
| Orders per status | Собирать метрики по статусам заказов; строить дашборды с конверсией между статусами |
| Time between statuses | Собирать метрики времени перехода заказов между статусами; строить аналитические отчёты и дашборды |
| SLA price calculation | Определить SLA по сложности; собирать метрики расчёта; алерты при нарушении SLA |
| CPU utilization | Собирать метрики CPU с каждого инстанса; дашборды с пороговыми алертами; рекомендации по масштабированию |
| Memory utilization | Собирать метрики памяти; алерты при превышении; рекомендации по оптимизации или увеличению ресурсов |
| DLQ messages count | Собирать количество сообщений в DLQ; алерты на рост; автоматизированные проверки ошибок |
